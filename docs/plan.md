# Implementation plan

Build the v2 design ([canvas](https://claude.ai/artifact/UpvfYeTSiM5oUmsncPjxYn), bottom row) on top of
[wowsims/forever](https://github.com/wowsims/forever). Feature scope: [features.md](features.md).
Work is split into lanes that subagents run in parallel, each in its own git worktree.

## 0. Decisions (defaults; change before Phase 0 ends if you disagree)

| Topic            | Decision                                                                                                                                                | Why                                                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Framework        | Nuxt 4, `ssr: false` for the app, prerendered static pages for `/` and `/data`                                                                          | Everything sims in the browser; no server needed for v1                                                 |
| Package manager  | pnpm 12.18 pinned in `packageManager`, `minimumReleaseAge: 10080` (7 days) and an `allowBuilds` allowlist in `pnpm-workspace.yaml`                      | Your 7-day rule. pnpm falls back to the newest version older than 7 days                                |
| Runtime          | Node 24 LTS for the app; Go 1.27 for the engine build only                                                                                              |                                                                                                         |
| Hosting          | Cloudflare Pages (static). One Pages Function later for armory lookup                                                                                   | Free, serves `.wasm` correctly, edge cache                                                              |
| Engine artifacts | Built in CI, uploaded as **GitHub Release assets on our repo** per engine version; `engine.lock.json` in git holds the upstream commit, URLs and sha256 | Keeps git small; old engines stay reachable so share links can re-run on the engine they were made with |
| Proto types      | `@protobuf-ts` (same as upstream) generated from the pinned tag's `proto/`                                                                              | Binary protos in and out of the WASM, matching upstream calls                                           |
| Styling          | Plain CSS with design tokens (custom properties) + small Vue primitives. No Tailwind, no component kit                                                  | The v2 look is custom; a kit would pull it back to generic                                              |
| Charts           | Hand-written SVG Vue components (histogram, line + band, forest plot, lanes, stacked outcome, diverging bar)                                            | Six chart types, all simple; a chart lib adds weight and its own look                                   |
| Name             | `forever/sim` placeholder                                                                                                                               | Open                                                                                                    |

The 7-day age rule covers npm packages only. Engine and game data are not npm packages and are meant to land the same day (hotfixes).

## 1. Repo layout

```
pnpm-workspace.yaml          # minimumReleaseAge, allowBuilds
engine.lock.json             # pinned upstream tag + artifact hashes
apps/web/                    # Nuxt app (pages, components, design tokens)
packages/proto/              # TS types generated from the pinned engine's .proto (regenerated by L1)
packages/contracts/          # shared types: Character, RunRecord, EngineClient interface (lead-owned)
packages/engine/             # WASM loader, worker pool, typed client, generated protos
packages/importers/          # SimC, WoWSims JSON, Wowhead URL → Character + diagnostics
packages/analysis/           # stats + derived metrics + run-note rules (pure TS, no DOM)
packages/gamedata/           # db.bin decode, item search index, presets, icons manifest
tools/engine-build/          # scripts the pipeline runs (build wasm, gen protos, smoke)
.github/workflows/           # engine-sync.yml, ci.yml, deploy.yml
```

Ownership rule: a lane edits only its own directories. `packages/contracts`, the root `package.json`
and `pnpm-lock.yaml` belong to the lead (me). Lanes add deps to their own `package.json`; the lead
regenerates the lockfile when merging.

## 2. What the engine gives us, and the gaps

Checked against upstream `proto/api.proto` and `sim/wasm/main.go`:

| v2 element                                              | Source                                                          | Status                                                                       |
| ------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Mean, σ, CI, p5/p95, histogram                          | `DistributionMetrics.avg/stdev/hist/all_values`                 | ✓                                                                            |
| Convergence chart                                       | running mean over `all_values`                                  | ✓ computed by us                                                             |
| Significance vs baseline                                | Welch t from two runs' avg/stdev/n                              | ✓ computed by us                                                             |
| Outcome bars per ability                                | `TargetedActionMetrics` hits/crits/glances/misses/dodges        | ✓                                                                            |
| Aura uptime lanes                                       | `AuraMetrics` + iteration-1 combat log (`RaidSimResult.logs`)   | ✓ for one iteration                                                          |
| **Mean DPS over time across all iterations, with band** | not produced by the engine                                      | ✗ v1 shows iteration 1 from the log; aggregated timeline = upstream PR later |
| Rage capped %                                           | `ResourceMetrics.gain` vs `actual_gain`                         | ~ approximate                                                                |
| Stat weights ± CI                                       | `statWeightsAsync` / `StatWeightsResult`                        | ✓                                                                            |
| Hit scaling                                             | N stat-shifted sims                                             | ✓ batch                                                                      |
| Top gear                                                | `bulkCandidates` + many `raidSimAsync`                          | ✓                                                                            |
| Multi-core                                              | `raidSimRequestSplit` / `raidSimResultCombination` in N workers | ✓                                                                            |
| Item data                                               | `assets/database/db.bin` (proto `UIDatabase`)                   | ✓                                                                            |
| Combat log parsing                                      | upstream `ui/sim/proto/combat_log` (MIT)                        | ✓ port, with credit                                                          |

## 3. Phases

### Phase 0: foundations (lead, serial, ~1 day)

> **Done 2026-11-12** on branch `phase-0`. Findings that changed the plan:
>
> - **Versioning.** Upstream's `v0.0.x` tags are stale, carried over from the TBC fork. An engine version is now the commit in `wowsims/pages-deploy` `forever/version.json`, currently `b2047bf`.
> - **Item data.** The WASM holds no item data. Each `Player.database` must carry items, enchants, suffixes, rand-prop points, **consumables and spell effects**. L2 builds this subset with L6's decoded DB.
> - **Engine specs.** There are 18 simulation specs, not talent trees. For example, DPS Warrior covers both Arms and Fury. Talent builds are presets on top.
> - **Determinism and speed.**
>   - WASM in Node matches the native Go build exactly for the same seed (850.1968 DPS).
>   - 5,000 iterations take about 10 s on one thread.
> - **Phase 0 test spec.** Only Hunter, Retribution Paladin and Protection Paladin ship complete upstream SIML presets. Phase 0 used Survival Hunter.
> - **Tooling.**
>   - pnpm 12 renamed `onlyBuiltDependencies` to `allowBuilds`.
>   - TypeScript stays on 6.0, because vue-tsc needs the compiler API that TypeScript 7 does not have.
>
> Details: `packages/engine/README.md`. Fixtures: `fixtures/`.

Nothing parallel starts until these exist, because every lane codes against them.

1. Scaffold the workspace: pnpm config with the age gate, Nuxt 4 app shell, TS strict, Vitest, ESLint, Prettier, `ci.yml` (typecheck, lint, test).
2. `packages/contracts`:
   - `Character` (class, spec, race, level, gear `{slot, itemId, enchantId, randomSuffix}`, talents string, consumables, buffs preset, encounter) with zod schema.
   - `EngineClient` interface: `computeStats`, `sim(req, {onProgress, signal})`, `statWeights`, `bulk`.
   - `RunRecord`: request, result, engine tag, data build, timestamp, seed.
   - `ImportResult`: `Character | null` plus `Diagnostic[]` with line, severity, code.
3. **Engine spike** (time-boxed, half a day): build `lib.wasm` from the pinned tag; run one Fury sim in **Node** with `wasm_exec.js`. Confirm how the sim gets item data (embedded in the WASM or passed in the request) and record it in `packages/engine/README.md`. This decides lane L2's loader.
4. Fixture pack in `fixtures/`: a real `RaidSimResult` and `StatWeightsResult` (binary + JSON) from the spike, 3 SimC exports, 1 WoWSims export. Lanes test against these, not the live engine.
5. Design tokens file from v2 (colors, type scale, spacing, chart palette validated by the dataviz check).

### Phase 1: parallel lanes (subagents, ~3–5 days wall time)

Six lanes, each a subagent in its own worktree (`isolation: "worktree"`), started together.

| Lane                  | Owns                                                                                                    | Builds                                                                                                                                                                                                                                                                                                                                                                                                                                        | Done when                                                                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **L1 Pipeline**       | `tools/engine-build/`, `.github/workflows/engine-sync.yml`, `engine.lock.json` format                   | Hourly job: read `wowsims/pages-deploy` `forever/version.json` (the commit wowsims.com serves) and compare it to the lock → build `lib.wasm.gz` at that commit (`wasm-opt -O3`, gzip) → regenerate `packages/proto` → copy `db.bin`, talent and icon assets → smoke-sim every spec in Node (no error, DPS within ±25% of last lock) → upload release assets → open PR updating the lock with a per-spec DPS delta table → auto-merge on green | Workflow runs on `workflow_dispatch` against two recent upstream commits and produces a correct PR. A failing smoke test blocks merge and opens an issue |
| **L2 Engine runtime** | `packages/engine/`                                                                                      | Load the WASM in workers, pool sized to `hardwareConcurrency`, split/combine, progress events, abort, typed wrappers for every `EngineClient` method, engine-version selection from the lock                                                                                                                                                                                                                                                  | Vitest in Node runs a fixture sim end-to-end; browser smoke page shows progress and cancel                                                               |
| **L3 Importers**      | `packages/importers/`                                                                                   | SimC parser (Forever addon flavor), WoWSims addon JSON, Wowhead planner URL; each returns `ImportResult` with line-level diagnostics; format auto-detection                                                                                                                                                                                                                                                                                   | Golden tests on all fixtures; an unknown item id produces a `DATA-03` diagnostic, not a throw                                                            |
| **L4 Analysis**       | `packages/analysis/`                                                                                    | CI, Welch t, histogram re-binning, percentiles, convergence series, outcome composition, rage-cap %, linear DPS estimate from weights (with propagated ±), run-note rules (`HIT-01`, `RES-02`, `DATA-03`, `CD-04`)                                                                                                                                                                                                                            | 100% pure functions with unit tests on fixture results; numbers match a hand-checked spreadsheet for one run                                             |
| **L5 UI kit**         | `apps/web/components/ui/`, `apps/web/components/charts/`, `apps/web/assets/tokens.css`, `/dev/kit` page | Panel grid, panel header, data table, key-value strip, segmented control, chips, diff rows, status glyphs, the six chart components (with hover tooltips and table fallback)                                                                                                                                                                                                                                                                  | `/dev/kit` renders every primitive with fixture data; matches v2 side by side; keyboard and screen-reader pass                                           |
| **L6 Game data**      | `packages/gamedata/`                                                                                    | Decode `db.bin`, item search index (name, slot, source, stats), enchant lists, spec presets from upstream, class colors, quality colors, icon URL map                                                                                                                                                                                                                                                                                         | Search "bracers" by slot=wrist, class=warrior in < 5 ms on fixture DB                                                                                    |

The lanes share nothing but `packages/contracts` and `fixtures/`, so none waits on another.
If a lane needs a contract change, it stops and reports. The lead changes `contracts` and tells the affected lanes.

### Phase 2: screens (2–3 subagents, ~4–6 days)

Starts once L2–L6 are merged (L1 can still be in review). Each screen is one subagent in its own worktree, owning its own `pages/` and `components/<screen>/` folder.

| Lane   | Screen                                                                                                                                                              | Uses                                |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| **S1** | Start: paste box with line markers, parse report, spec picker, recent runs, data/engine status, tuning chart (from L1's per-spec delta history)                     | L3, L6, contracts                   |
| **S2** | Workbench: gear table with value column, item picker sheet, pending-changes diff, stats run/draft/Δ, caps panel, sim bar; talents, buffs, fight and rotation tabs   | L2 `computeStats`, L4 estimates, L6 |
| **S3** | Run analysis + Top gear: KPI strip, distribution, convergence, timeline (iteration 1), ability table, weights, hit scaling, run notes; top-gear ranking forest plot | L2, L4, L5 charts                   |

Shared app state (current character, draft, runs) lives in one Pinia store that the lead writes first, on day 1 of Phase 2, before S1–S3 start.

### Phase 3: whole-app features (lead + 1 subagent, ~2–3 days)

- Share links: character + settings + engine tag, compressed into the URL fragment. Opening one loads the pinned engine version.
- Local history in IndexedDB; "older engine" flags.
- Offline: service worker caches the app, WASM and data for the current engine tag.
- Credit to WoWSims (MIT) in the footer and on the data page.
- Playwright e2e: paste SimC → workbench → sim → analysis; top gear with 3 candidates; share link round trip.
- Performance budget: first load ≤ 300 KB JS before the WASM; WASM fetched in parallel and cached.
- Deploy pipeline to Cloudflare Pages; preview deploys per PR.

### Later (not in this plan)

Droptimizer, armory lookup (after a spike on Blizzard's Forever profile namespace), saved variants with side-by-side compare, aggregated timeline (upstream PR), public tuning-history page, guild roster.

## 4. Running the subagents

- **Briefs.** Each lane gets: the goal, its owned paths, the contract files to code against, the fixtures, the "done when" line from the table, and the test command. Each is told not to touch paths outside its lane.
- **Isolation.** Every lane runs with `isolation: "worktree"` and commits to its own branch `lane/<id>`.
- **Merge order.**
  - Phase 1: L4 → L6 → L3 → L2 → L5 → L1.
  - Phase 2: S1, S2 and S3 in any order.
  - On each merge the lead reruns `pnpm install`, typecheck and the full test suite.
- **Concurrency.**
  - Phase 1 runs 6 subagents, Phase 2 runs 3.
  - Each review is one more agent looking at the diff cold, without the author's reasoning.
- **Review.** Before merging a lane, the lead reads the diff and runs `/code-review` on it.
- **Contract changes.**
  - Only the lead edits `packages/contracts`.
  - A lane that needs a change stops and reports with the proposed change.

## 5. Risks

| Risk                                                  | Mitigation                                                                             |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Upstream changes proto shape between tags             | Generated types are per engine tag; smoke tests in L1 fail the bump PR, not production |
| Item data not reachable the way we assume             | Phase 0 spike settles it before lanes start                                            |
| Engine accuracy questioned (Forever is weeks old)     | Every result shows engine tag and data build. Run notes flag missing items             |
| 7-day age gate blocks a needed fix                    | `minimumReleaseAgeExclude` for that one package, documented in the PR                  |
| Upstream asks for visible credit (MIT notice request) | Footer credit plus the data page, from day one                                         |
| Mean-over-time timeline not available                 | Ship iteration-1 timeline in v1, label it, propose an upstream change                  |
